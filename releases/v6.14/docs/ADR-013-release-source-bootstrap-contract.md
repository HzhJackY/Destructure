# ADR-013：发布线源码构建与回补合同

状态：已采纳（v6.14 起）  
日期：2026-08-24

## 决策

新发布线必须以参考版本的**完整允许源码树**创建，而不是以历史 `source_file_manifest.csv` 作为复制白名单。历史 manifest 仅是冻结证据，可能已经滞后，不能定义源码闭包。

允许源码树递归包含参考版本中的代码、测试、工具、文档和版本配置；必须排除：`.git`、虚拟环境、`__pycache__`、DATA_HOME、真实 PDF、Golden corpus、数据库、缓存、日志、输出、本机配置和任务临时文件。

创建流程固定为：

1. 冻结参考版本允许源码树的路径、大小与 SHA-256。
2. 完整复制该树到新版本；复制后逐文件 hash 必须相等。
3. 对新版本执行内部导入闭包、`py_compile` 与最小应用/后端导入检查。
4. 仅在上述 parity 通过后，才允许版本特定代码修改；修改必须进入 Change Report。

`tools/release_source_bootstrap.py` 是执行此合同的唯一工具。`--backfill-missing` 只能补目标版本缺失的允许文件，永不覆盖已有目标文件；`--strict-baseline` 只用于尚未开始版本特定修改的新发布线。

## v6.14 回补规则

v6.14 已含金融投资定点修改，因此不能重新覆盖复制。本次仅从 v6.13 回补缺失的允许源码文件，逐文件 hash 与 v6.13 一致；已存在但 hash 不同的文件作为 v6.14 修改记录保留，不得自动回滚。

## 后果

发布前必须报告：参考允许文件数、目标缺失数、回补列表、hash 差异列表、内部导入闭包结果和最小 UI/后端导入结果。任一缺失或导入失败均为 `RELEASE_SOURCE_INCOMPLETE`，不得进入正式验收。
