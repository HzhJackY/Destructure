# INC-045：中国人保投资组合表头带与 OCR 日期基线

## 症状

中国人保 2023、2025 投资组合物理页可由 Native 标题/分类轴/单位定位，但 Native 数值层不完整。旧条件 OCR 使用硬编码 PSM 6，并将金色/棕色宽表头带按红章逐像素清除，导致白色期间标题和大量表格数值消失；2023/2025 因此不能通过 Stage A 期间与金额门禁。

## 根因

Document Index profile 声明的布局模式没有传到 Tesseract 执行层，OCR 缓存身份也未表达实际 PSM。红章预处理只看像素颜色，不区分紧凑印章和横跨页面的结构性表头。改用 PSM 4 并保留宽色带后，Tesseract 又会把 `YYYY/31日` 与 `年12月` 放在相邻基线；安全的行文本正则禁止跨行拼接，所以仍漏日期。

## 修复

- Fast Index 执行并缓存 profile 的 PSM 4，缓存身份包含 PSM 和预处理版本。
- 红章清理保留红色像素覆盖超过页面宽度 35% 的结构性行带，仅清除紧凑红色区域。
- Direct Portfolio 仅在 Native 物理身份充分、数值层不足时 OCR 已定位页，继续使用唯一 Fast Index/Tesseract 管线。
- 日期只通过 OCR 词级 BBox 在同一视觉带内按 `YYYY→年→MM→月→DD→日` 横向重建；缺组件不推断，文本正则仍禁止任意跨行拼接。
- 同一年份的完整日期会取代叙述文字中的裸年份，防止一个期间的两个精度变体伪装成两列。

## 回归边界

中国人保 2023/2024/2025 投资组合真实 Stage A 分别定位物理页 42/41/39，期间与两期总额匹配独立 Golden，三份均为唯一 `RECOMMENDED/PRESELECTED`。2024 保持 Native-only；2023/2025 只 OCR 已定位候选页。未运行 Capture、Canonical、Merge 或浏览器 E2E。
