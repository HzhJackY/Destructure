# v6.9 架构说明：金融提取引擎 V2

## 版本边界

`releases/v6.9` 是独立代码快照；共享 `DATA_HOME`、PDF、物理 Capture 和 SQLite 元数据。v6.8 不会被修改。SQLite 迁移只增加表，不重写历史机器证据；回退旧代码不会删除新数据，但旧版本不会识别 v6.9 的附注容器/表块附加信息。

## 附注容器与逻辑表块

一次请求仍只经过 `CaptureService → CaptureOrchestrator`。原始结果先成为 `NoteContainer`，再由布局、叙述分隔、来源块及表头拓扑证据分为 `TableBlock`。每个表块有自己的捕获目录、质量状态、审计证据和逻辑资产身份。没有分段证据时保留为一张表，禁止猜测性拆表。

## Statement Anchor

`STATEMENT_ANCHOR` 是专用的几何原语：从主报表父项抓取父行和连续缩进子项，父行允许无金额；子项保存金额、附注编号和来源 bbox。它不通过“附注标题以下的 ROI”取表头，因此不会丢失主报表上方的口径/期间信息。

## 质量门与审核

机器证据不可变；人工操作只写入 `block_adjudications`；认证状态由二者物化。除旧的边界、表头、隐式合计检查外，v6.9 还要求表头拓扑不歧义，且勾稽不出现显式 WARNING。`逻辑资产工作区` 是附注容器、表块、勾稽、版本与裁决的唯一单资产详情入口；`审核收件箱` 仅提供队列、筛选和路由。

## 学习层

只保存结构标签和可解释的层级回退排序：行业 → 公司 → 文件类型 → 报表类型 → 口径 → 表族 → 子表。ML/LLM 只能排序候选/置信度和选择 abstain，不能产生或改写财务金额。

## 已知范围

复杂跨页表、并列小表、图片型页及跨表勾稽仍会进入 `REVIEW_REQUIRED`，不以自动化取代人工审计。真实样本仅对新华保险 2023 主报表锚点作了本地验证；完整跨公司黄金集仍需在 UI 流程中逐份认证。
