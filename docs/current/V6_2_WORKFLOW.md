# v6.2 工作流与审计边界

## 批量表族抓取

在“整表批量工作台”选择多个 PDF，再选择内置或自定义表族。系统为每个 `PDF × 目标表` 创建独立 Job；每个 Job 的状态、错误、重试关系和批次汇总均持久化到 SQLite 与批次审计 JSON。

`投资相关收益` 表族用于处理“投资净收益”在不同年份拆分为“投资收益”和“利息收入”的披露变化。它只判定 schema variant，绝不在抓取阶段把两张来源表强行加总或覆盖。

## 结构层

结构层从导出的长表派生 `row_path`、父行、置信度和证据。推断同时参考显式父级、行层级、行序、总计/小计语义；不把缩进当作唯一依据。低置信结论应进入人工复核。

重复行名以 `row_path` 区分，例如：

```text
股息及利息收入 / 股息收入 / 交易性金融资产
股息及利息收入 / 利息收入 / 交易性金融资产
```

因此两行不会被静默合并。

## 小计核对

小计核对是 warning-only。容差基于展示单位（元、万元、百万元、亿元）以及子项数量，结果为 `PASS`、`PASS_WITH_ROUNDING` 或 `WARNING`。来源数值、机器 JSON 和原始 PDF 证据均不因核对结果被修改。

## 合表冲突策略

- 不同 `year / scope / restated` 维度是合法并存，不属于冲突。
- 多个物理列因 year 或 scope 缺失而产生多个值：`REVIEW_REQUIRED_DIMENSION_AMBIGUITY`，需要补维度后再进入研究宽表。
- 完全相同经济键且数值不同：`VALUE_CONFLICT`，继续阻断。

## 本地 LLM 设置

复制 `config/llm_config.example.yaml` 为 `config/llm_config.yaml` 后填写本地凭据。该文件不应提交版本控制，也不会写入 SQLite、Capture 审计或交付 ZIP。环境变量仍优先于本地配置。
